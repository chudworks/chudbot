# Vibe coding manual

Work only inside `/workspace`. This is a React 19, TypeScript, Vite, and SCSS
site managed with Bun. Inspect the existing project before editing. Use
`bun add <registry-package>` for public npm packages and keep `bun.lock`.
The `read` and `edit` tools accept workspace-relative paths such as
`src/App.tsx` and canonical paths beneath `/workspace`; use Bun or Node for
scripts because Python is not installed.
Never add Git, URL, `file:`, or `link:` dependencies, `.npmrc`, `bunfig.toml`,
backend code, secrets, or a top-level `__vibe` path.

Run `bun run build` before finishing. The deployed clean build is performed by
Chudbot after you stop, so do not commit or deploy. Finish with a short factual
summary.

The global `vibe` object is typed by `src/vibe.d.ts`. Call
`await vibe.identity()` to get the signed-in viewer's public Discord display
identity, guild display name, and site name. It returns `null` for public
sites, whose viewers are anonymous. Do not assume identity is available before
the promise resolves. `src/vibe.d.ts` is generated by Chudbot before every
build; never edit it. Use browser-side public APIs only.

For durable site data on a protected site, use a site-local collection. Public
sites cannot use collections: every collection read, write, delete, count, or
watch fails with `collections_unavailable`. Collection names are short safe
identifiers. Documents are JSON objects and receive an `id` UUID plus
`inserted_by`, `inserted_at`, `updated_by`, and `updated_at`. These automatic
fields cannot be chosen by site code. Passing a returned document back to
`put` or `update` is safe because Vibe recomputes its audit fields.

```ts
type Score = { user: string; score: number; details?: VibeJsonValue };
const scores = vibe.collection<Score>("scores");

const created = await scores.put({ user: "123", score: 10 });
const updated = await scores.put({ ...created, score: 20 });
const leaders = await scores
  .where({ user: ["123", "456"] })
  .orderBy("score", "desc")
  .limit(5)
  .find();
```

`put` inserts when no `id` is present and updates only an existing document
when `id` or `_id` is supplied. A missing supplied id is an error. `insert`
always creates a new document and `update` requires an existing id. Queries
support `where`, `limit`, `offset`, `orderBy(column, "asc" | "desc")`,
`select([...])`, `distinct()`, and terminal `find()`, `count()`, `delete()`, or
`deleteOne()`. `deleteOne` fails rather than deleting when its final query
would select more than one document. A `where` value is either one JSON scalar
or a list of scalar alternatives. Stored arrays and objects are returned but
never match filters; do not model fields that need filtering as JSON objects.
Ordering supports numbers, strings, and ISO timestamp strings.

Use `watch` when the page needs best-effort live notifications for collection
changes. Only the query's `where` criteria apply to a watch. Keep the returned
watch and disconnect it during component cleanup.

```ts
const watch = await scores.where({ user: "123" }).watch((change) => {
  console.log(change.type, change.document);
  // Updates can enter or leave the filter; inspect these flags when maintaining
  // a live result list.
  console.log(change.matchesBefore, change.matchesAfter);
});

await watch.disconnect();
```

Insert notifications have `before: null`, deletes have `after: null`, and
updates include both versions. Watches are process-local and ephemeral: they
do not replay missed events and disconnect when Chudbot restarts. Use
collections for persistence and rooms for transient peer interaction; do not
try to make room state durable in browser storage.

For ephemeral realtime collaboration within this site, use a site-local room:

```ts
const room = vibe.room("topic");
room.on("event", (event, user) => console.log(event, user));
room.on("user:join", (user) => console.log("joined", user));
room.on("user:quit", (user) => console.log("left", user));
room.onUserState("presence", (user, before, after) => {
  console.log(user, before, after);
});

const connection = await room.join();
await connection.setUserState("presence", { status: "online" });
await connection.broadcast({ text: "hello" }, "event");
console.log(connection.users);
await connection.disconnect();
```

`broadcast` takes `(event, label)`. Room names, event labels, and state keys are
short safe identifiers. Labels beginning with `user:` are reserved for Vibe's
implicit presence events. Room data is in memory, disappears when users leave
or Chudbot restarts, and is strictly isolated to this site. Protected sites use
Discord display identity; public sites get a stable anonymous browser id.
Event and state values may be any JSON-serializable value: primitives, arrays,
or objects. The SDK serializes them as JSON, so unsupported JavaScript values
such as `undefined`, functions, `BigInt`, and cyclic objects throw.

Client-side routing must tolerate a direct navigation or refresh: Chudbot
serves `index.html` for document requests that do not match a built file.
Build a polished, responsive site with accessible HTML, clear hierarchy,
deliberate typography, and useful empty/error states.
